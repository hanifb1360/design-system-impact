# Design System Impact v0.1.0

The first release establishes a deterministic pipeline for understanding design-system evolution and preparing constrained migration work for developers and coding agents.

## Highlights

- Versioned React/TypeScript component and design-token snapshots
- Semantic classification of component, prop, export-path, and token changes
- Consumer JSX and token impact analysis with workspace and CODEOWNERS attribution
- Package subpath and multi-level local barrel tracing
- Explicit migration guidance for safe prop-value and token replacements
- Agent-ready migration manifests with observed facts kept separate from maintainer guidance
- Human-readable terminal, JSON, and Markdown reports
- Stable diagnostics for unsupported or uncertain analysis, including JSX spreads
- Published Draft 2020-12 JSON Schemas for every persistent artifact
- CI-friendly exit codes and a reusable programmatic API

## Design philosophy

The package works locally without an LLM or hosted service. Deterministic analysis provides facts and bounded tasks; an AI coding agent or developer performs the edits; `design-system-guard` validates the migrated result against design-system policy.

## Demonstration

The public [`design-system-impact-demo`](https://github.com/hanifb1360/design-system-impact-demo) repository exercises a realistic `@acme/ui` 1.4 → 2.0 migration, including package subpaths, React wrappers, barrels, aliases, tokens, ownership, explicit migration mappings, and Guard validation.

## Known limitations

The initial release intentionally does not execute codemods. TypeScript path aliases, namespace imports, CommonJS forwarding, deep data-flow through prop spreads, wildcard package exports, and full CODEOWNERS grammar remain future work.
